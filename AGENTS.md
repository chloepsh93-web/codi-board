# Project working rules

## Explicit consent before feature changes

- Do not add, remove, or change any feature or its behavior without the user's explicit consent to that specific scope.
- A request to fix an image, text, layout, or data item authorizes only that requested correction. It does not authorize adjacent feature changes, redesigns, or refactors that change behavior.
- Before proposing a feature change, describe what will change and its user-visible effects. Wait for explicit consent before implementing or deploying it.
- Broad requests to improve, inspect, or cross-check the service do not authorize new features. Present proposed behavior changes for consent first.
- Previously approved work may proceed within its agreed scope; do not repeatedly ask for the same consent. New scope requires new consent.
- Preserve private wardrobe data and photos outside the public repository and deployment.

This is an agent instruction and review gate, not an executable hook. Do not claim that an automatic hook was installed unless it was actually configured and verified.
